# 3x-ui Server Setup — новая версия: SSL для домена или IP

Интерактивный установщик официальной панели [MHSanaei/3x-ui](https://github.com/MHSanaei/3x-ui) для **нового Ubuntu 22.04 или 24.04 VPS**. Старый репозиторий `3ax-server-setup` не затрагивается. Подход к SSH и Fail2ban основан на ранее созданном установщике.

**Основной сценарий:** запускаешь **одну команду**, выбираешь собственный домен, если он есть. Если нет — получаешь **настоящий сертификат Let's Encrypt для публичного IPv4**. Заходишь в панель по HTTPS, **сам** восстанавливаешь свою базу `.db`, после чего запускаешь короткую команду, чтобы настроить проксирование VPN и подписки. При установке база не нужна.

> Важно: это скрипт только для **чистого VPS**. Он меняет SSH, UFW и Nginx. Сделай snapshot, убедись, что доступна веб-консоль провайдера. Скрипт откажется работать поверх уже установленной панели или Nginx.

## 1. Публикация и установка

В новом GitHub-репозитории `evgeny-dmitrievich/3x-ui-server-setup` (ветка `main`) должны находиться `setup.sh`, `configure-after-import.sh`, `db_tool.py`, `README.md` и тесты. Пока файлы **не опубликованы**, команда ниже в GitHub не работает. **Никогда не публикуй** приватную базу, VPN-ключи, пароли или сертификаты.

```bash
curl -fsSL https://raw.githubusercontent.com/evgeny-dmitrievich/3x-ui-server-setup/main/setup.sh -o /tmp/3x-ui-setup.sh && sudo bash /tmp/3x-ui-setup.sh
```

Установщик попросит:

1. Подтвердить установку (`YES`).
2. `Есть собственный домен, указывающий прямо на этот сервер? (y/N)`.
   - **Да:** введи свой DNS-домен, например `vpn.example.org` (его A-запись должна указывать **на публичный IP VPS**, без Cloudflare HTTP-проксирования).
   - **Нет или Enter:** скрипт сам определит публичный IPv4 и попросит Let's Encrypt выдать SSL на IP.
3. Контактный email для сертификата.
4. Имя нового SSH-пользователя, пароль для `sudo` и **публичный SSH-ключ**.
5. Проверить подключение по SSH `1335` из другого терминала; **до этого порт 22 не закрывается**.

Для ACME-проверки должен быть открыт **TCP-порт 80 со стороны интернета**, в том числе в панели управления VPS-провайдера. IP-адрес должен быть публичным и маршрутизироваться на сервер. При ошибке выпуска сертификата установка **останавливается**, не подменяя его самоподписанным и не открывая панель без HTTPS.

Официальный установщик 3x-ui поддерживает `XUI_SSL_MODE=domain|ip` и использует `acme.sh`. Обычный сертификат домена имеет срок порядка 90 дней; сертификаты IP действуют **около 6 дней** и требуют автоматического продления. Продление настраивается штатным `acme.sh` и обновляется для Nginx после импорта.

## 2. Что создаётся на новом сервере

- Официальная свежая стабильная **3x-ui**, пока со своей **пустой базой**, уникальным логином и паролем.
- **HTTPS** по внешнему TCP `443` сразу после установки: временный `Nginx Stream` пропускает зашифрованный трафик в панель на локальном порту `13350` (TLS завершает сама панель).
- Новый SSH-пользователь с `sudo`, SSH-порт `1335`; после проверки входа отключаются root-login, вход SSH по паролю и порт `22`.
- **UFW** с минимально необходимыми портами и **Fail2ban** для SSH.
- Инструмент `3x-ui-after-import` для второго этапа, а также защищённый файл `/etc/3x-ui-setup/bootstrap.env` с адресом и путями сертификатов (без паролей).

| Открытый порт | Для чего |
|---|---|
| `1335/tcp` | SSH по ключу |
| `80/tcp` | HTTP-01 выпуск и автоматическое продление сертификатов |
| `443/tcp` | HTTPS-панель до импорта, VPN + HTTPS после импорта |
| `13133/tcp` | Прямой VLESS Reality из нашей базы |
| `443/udp` | Hysteria2 |
| `8444/udp` | TUIC |
| `51821/udp` и `51822/udp` | AmneziaWG из нашей базы |

Внутренние порты панели, подписок и WS/gRPC/MTProto не открываются напрямую во внешний интернет. Если провайдер VPS использует дополнительный firewall, эти порты требуется разрешить и там.

## 3. Вход в панель по HTTPS до импорта

На сервере посмотри выданные официальным установщиком параметры:

```bash
sudo cat /etc/x-ui/install-result.env
```

Узнай значение `XUI_WEB_BASE_PATH` и используй его в браузере:

- **С доменом:** `https://vpn.example.org/ТВОЙ_СЛУЧАЙНЫЙ_ПУТЬ/`
- **Без домена:** `https://ПУБЛИЧНЫЙ_IP/ТВОЙ_СЛУЧАЙНЫЙ_ПУТЬ/`

Порт `13350` наружу не открывается: Nginx передаёт TCP 443 на панель. Если HTTPS не выдаётся, сначала проверь доступность TCP 80 из интернета и DNS/доступность публичного IP. Скрипт не создаёт недоверенных сертификатов.

## 4. Восстановление базы через панель

Открой в панели раздел резервных копий и восстанови **свою** базу `.db` вручную (например, итоговую базу из нашей переписки после исправления MTProto). Никакая база в GitHub не хранится и не устанавливается автоматически.

**Ожидаемое поведение:** после восстановления база может вернуть старый порт панели, её путь и SSL-настройки, из-за чего временный адрес перестанет открываться. Это не означает, что установка сломалась. Следующий шаг выполняется через SSH, а не через панель.

## 5. После импорта: одна короткая команда

```bash
sudo 3x-ui-after-import
```

Ни домен, ни IP, ни email повторно вводить не требуется. Команда берёт адрес и файлы действующего сертификата из `/etc/3x-ui-setup/bootstrap.env`, затем:

- Создаёт согласованный резервный снимок восстановленной SQLite-базы.
- Проверяет структуру конкретной базы этого проекта (не пытается угадывать конфигурацию произвольной 3x-ui).
- Подготавливает отдельную копию, обновляет внешний адрес хостов и подписок, пути сертификатов; **не меняет клиентские UUID, REALITY-ключи и статистику**.
- Заменяет временный маршрут HTTPS `443 -> 13350` на полноценный Nginx с распределением по SNI; проксирует VLESS, XHTTP, WebSocket, Trojan-gRPC, MTProto и веб-пути.
- Проверяет Nginx и восстанавливает резервные файлы при ошибке.
- Обновляет команду `acme.sh` при автопродлении так, чтобы она перезагружала **Nginx и x-ui**.

Итоговые учётные данные панели лежат в `/root/3x-ui-after-import-*/panel-access.txt` с правами только для root. Если первый этап не создавал `/etc/3x-ui-setup/bootstrap.env` (старый скрипт), сохранён совместимый режим с параметрами `--domain ... --email ...`.

**Примечание о SNI:** чужие домены (например, `apple.com`) в настройках REALITY **не равны** твоему адресу сайта для SSL и подписок. SSL выпускается исключительно на твой реальный домен или IP VPS. При доступе к REALITY используется собственный SNI из базы независимо от выбора домена панели.

## 6. Проверки и диагностика

```bash
sudo systemctl status x-ui nginx fail2ban --no-pager
sudo ufw status numbered
sudo fail2ban-client status sshd
sudo nginx -t
sudo /root/.acme.sh/acme.sh --list
sudo ss -lntup | grep -E ':(1335|443|13133|8444|51821|51822)\b'
sudo journalctl -u x-ui -n 100 --no-pager
```

После импорта проверь работу VPN **с другого устройства**: корректность подписок, всех протоколов и MTProto, реальные SNI, проверку сертификатов. Успешный `nginx -t` или целостность SQLite не равны проверке реальной доступности VPN.

### Локальные проверки проекта перед публикацией

```bash
bash -n setup.sh
bash -n configure-after-import.sh
python3 -m py_compile db_tool.py
python3 test_bootstrap.py
python3 test_db_tool.py /path/to/private.db
```

**Статус:** тесты синтаксиса и преобразования базы выполняются локально. Полный установщик ещё не запускался на реальном свежем VPS, поэтому сначала протестируй на временном сервере со snapshot и доступом к консоли провайдера. Код не опубликован в GitHub автоматически.
