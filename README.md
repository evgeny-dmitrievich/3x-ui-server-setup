# Выпуск 2.5 — VLESS Reality через TCP 443

В новой установке **13133/TCP не открывается в UFW**. После импорта приватной базы команда
`sudo 3x-ui-after-import` автоматически переводит только именованный inbound `VPN`
на SNI **`dl.google.com`**, REALITY target `dl.google.com:443` и внутреннее прослушивание
`127.0.0.1:13133`, а в разделе «Хосты» создаёт/обновляет адрес VPN с внешним портом **443**.
Nginx направляет SNI `dl.google.com` в этот внутренний inbound **без PROXY protocol**.
У UUID, коротких идентификаторов, ключей и других подключений значения не меняются.
Порт `443/TCP` остаётся общим для Nginx и сайта-заглушки; все прежние маршруты сохраняются.

Для **уже работающего сервера**, где `3x-ui-after-import` выполнен ранее,
используйте **только** новый однократный помощник:

```bash
sudo bash reality-443.sh
```

Его можно скачать с GitHub после публикации в репозитории `3x-ui-server-setup`.
Он самостоятельно делает согласованную резервную копию SQLite и конфигурации Nginx,
изменяет только VPN и привязанный Host, проверяет запуск Xray/Nginx, удаляет правило
UFW для TCP `13133`. При ошибке до завершения переключения выполняется откат.
**Не используйте `sudo 3x-ui-after-import` повторно** на действующем сервере.

После смены SNI нужно обновить подписку Shadowrocket или вручную изменить SNI
ранее сохранённых профилей. При наличии отдельного старого профиля `apple.com:13133`
он перестанет работать. Реальный клиентский доступ по Reality следует проверить
отдельно: локальные проверки служб не заменяют VPN-тест.

# Выпуск 2.4 — стабильность обновлений

Этот выпуск не меняет VPN-схему, порты, профили WireGuard или логику
импорта базы. Перед любыми изменениями SSH/UFW `setup.sh` скачивает и
проверяет полный комплект файлов одной версии и сравнивает опубликованный
`setup.sh` с запущенным. Затем пользуется только проверенными локальными
копиями файлов. При неполной публикации GitHub установка остановится
раньше изменения SSH и firewall.

`3x-ui-after-import` проверяет совместимость своей версии с `db_tool.py`,
ожидает готовности HTTPS-панели, проверяет маршруты через Nginx, заглушку
и 404 и откатывает конфигурацию при ошибке. SSL внешнего сертификата
проверяется дополнительно (ошибка доверия предупреждает, но сама по себе
не выключает рабочую панель). Существующие логин, пароль, путь и UUID
не изменяются.

**На уже работающем сервере переустановка не нужна.** Обновление GitHub
не заменит автоматически установленные файлы. Если используешь текущую
работающую версию 2.3, оставь её до отдельного обновления помощников.

Перед публикацией всего содержимого архива запусти:

```bash
python3 test_release_integrity.py

python3 test_db_tool.py /path/to/private.db
```

# 3x-ui Server Setup — безопасная установка и смена IP/домена

**Версия:** 2.2 · 23.11.2026. **Отдельный проект** для официальной 3x-ui от MHSanaei; не изменяет прежний `3ax-server-setup`.

Установка рассчитана на **новый Ubuntu 22.04/24.04 VPS** с публичным IPv4, доступом к консоли провайдера и snapshot. Скрипт **не импортирует приватную базу**. Она восстанавливается через веб-панель после установки. Не запускайте установщик на действующем сервере с уже настроенным SSH, UFW или Nginx.

## 1. Публикация и установка одной командой

Создайте отдельный GitHub-репозиторий `evgeny-dmitrievich/3x-ui-server-setup`, ветку `main`, и поместите **в корень** файлы из архива проекта: `setup.sh`, `resume-after-fail2ban.sh`, `configure-after-import.sh`, `change-domain.sh`, `stack-manager.sh`, `db_tool.py`, каталог `landing/` (включая `index.html`, `404.html`, `install.sh`) и каталог `wireguard/` (включая `setup.sh`, `manage.sh`), `.gitignore`, README и тесты. До их публикации следующая команда скачает старую версию либо вернёт 404:

```bash
curl -fsSL https://raw.githubusercontent.com/evgeny-dmitrievich/3x-ui-server-setup/main/setup.sh -o /tmp/3x-ui-setup.sh && sudo bash /tmp/3x-ui-setup.sh
```

Скрипт установит актуальную стабильную 3x-ui (официальный установщик `install.sh`), Nginx Stream, **отдельную статическую страницу о природе с красивой 404**, UFW, Fail2ban и **самостоятельный WireGuard с двумя клиентскими профилями**. Попросит выбрать **свой домен или IP**, email для ACME, SSH-логин, пароль sudo и публичный SSH-ключ. SSH будет доступен по порту **1335** с авторизацией ключом; старый порт 22 закрывается **только после успешного входа из второго терминала**. Проверка Fail2ban ограничена 12 секундами. Шрифт Linux-консоли готовится для кириллицы без изменения языка всей ОС.

Сертификаты для домена и публичного IP выдаёт Let's Encrypt через механизм 3x-ui/acme.sh. Для IP используются короткоживущие сертификаты (~6 дней): автоматическое продление критически важно. TCP 80 должен оставаться доступным для HTTP-01 (включая внешний firewall провайдера). Без корректного сертификата установка остановится.

**Важно:** скрипт меняет SSH и firewall. При тестировании держите открытой веб-консоль VPS. Не публикуйте приватную базу, сертификаты, логины, ключи или `bootstrap.env` в GitHub.

## 2. Порты UFW

| Назначение | Порт |
|---|---|
| SSH | 1335/TCP |
| ACME-проверка | 80/TCP |
| Nginx / HTTPS / VPN TCP | 443/TCP |
| VLESS Reality через Nginx | 443/TCP (внутренний `127.0.0.1:13133`) |
| Hysteria2 | 443/UDP |
| TUIC | 8444/UDP |
| AmneziaWG / AWG 3.1 | 51821/UDP, 51822/UDP |
| Отдельный WireGuard (wg0) | **51820/UDP** |

Внутренние веб-порты 3x-ui, MTProto, XHTTP, WS и gRPC открывать снаружи не нужно. Состояние портов определено для нашей объединённой базы; если она менялась, проверьте их заново.

## 3. Публичная страница-заглушка

На обычном адресе `https://ДОМЕН-ИЛИ-IP/` появится небольшая русскоязычная страница **«Тихие маршруты»**: горное озеро, лес, тишина, чай и пирожки. Пейзаж — оригинальная встроенная SVG-иллюстрация, без внешних картинок, шрифтов, аналитики или JavaScript. Страница не упоминает VPN или 3x-ui.

Файлы хранятся в `/var/www/3x-ui-landing/index.html` и `/var/www/3x-ui-landing/404.html`; их можно позже изменить самостоятельно. Неизвестные публичные пути показывают страницу **404 «Тропа не найдена»** с рабочей кнопкой «Вернуться на главную». Статус ответа остаётся **HTTP 404**; приватные маршруты панели и подписок при этом не переписываются. При переключении IP ↔ домен страница сохраняется. При импорте базы `3x-ui-after-import` также оставляет её на публичном `/`, а панель доступна только по её отдельному, уже существующему пути.

**Важно:** публичная заглушка не является средством защиты панели и не скрывает открытые VPN-порты: безопасность обеспечивают отдельный путь, учётные данные, настройки доступа и firewall. Заглушка не меняет REALITY SNI и параметры протоколов.

## 4. Отдельный WireGuard — профили «Роутер» и «Роутер (Катя)»

В первой установке автоматически настраивается **обычный WireGuard**, независимый от Xray и 3x-ui. Он слушает **UDP 51820** и не конфликтует с портами AmneziaWG 51821 и 51822. Веб-панель для WireGuard не устанавливается, чтобы не открывать дополнительный административный интерфейс.

Сразу создаются **два самостоятельных профиля с разными ключами**:

| Имя файла | VPN-адрес |
|---|---|
| `Роутер.conf` | `10.73.20.2/32` |
| `Роутер (Катя).conf` | `10.73.20.3/32` |

Оба файла сохраняются **только на сервере**, доступны root в `/etc/wireguard/clients/` (права 600) и не публикуются в GitHub, на главной странице или через публичный веб-интерфейс. На первом запуске их приватные ключи генерируются непосредственно на сервере; **в архиве проекта готовых ключей нет**. Предполагается IPv4-туннель со всем IPv4-трафиком через VPN; IPv6 не маршрутизируется через этот профиль. Перед импортом на роутер проверьте поддержку обычного WireGuard и при необходимости настройте маршрутизацию локальной сети средствами роутера.

После установки войдите под созданным SSH-пользователем и выполните:

```bash
sudo 3x-ui-wg status
sudo 3x-ui-wg list
sudo 3x-ui-wg export all
```

Последняя команда скопирует оба профиля в **`~/wireguard-profiles/`** только для текущего SSH-пользователя, с правами 600, чтобы их можно было забрать через SFTP или командой SCP со своего компьютера:

```bash
scp -P 1335 'SSH_USER@SERVER_IP:wireguard-profiles/Роутер.conf' .
scp -P 1335 'SSH_USER@SERVER_IP:wireguard-profiles/Роутер (Катя).conf' .
```

Замените `SSH_USER` и `SERVER_IP` на собственные. Держите скачанные `.conf` в секрете — **они содержат приватные VPN-ключи**. После скачивания можно удалить экспортированные копии из домашней папки, оставив оригиналы только в защищённом каталоге root.

Позже можно добавить новый профиль без перезапуска WireGuard:

```bash
sudo 3x-ui-wg add 'Ещё один роутер'
sudo 3x-ui-wg export 'Ещё один роутер'
```

`3x-ui-change-domain` не меняет WireGuard: исходные профили используют публичный **IPv4 сервера**, а не домен. При смене самого IP сервера потребуется отдельно обновить `Endpoint` профилей на новый адрес и импортировать файлы повторно. Не открывайте UDP 51820 в Nginx: WireGuard использует напрямую UDP.

## 5. Восстановление базы и завершение настройки

После установки откройте панель по адресу `https://ДОМЕН-ИЛИ-IP/СЛУЧАЙНЫЙ_ПУТЬ/`; данные доступа созданной пустой панели хранит официальный установщик в `/etc/x-ui/install-result.env` (доступ только root).

**Самостоятельно** загрузите нужную `.db` в разделе резервных копий панели. В базе могут храниться старые порты или сертификаты, поэтому доступ к панели после восстановления временно может пропасть до следующей команды.

```bash
sudo 3x-ui-after-import
```

Помощник:

- Делает резервную копию импортированной SQLite **через SQLite backup API**, включая данные WAL.
- Создаёт отдельную подготовленную копию и генерирует Nginx-конфигурацию.
- Сохраняет **логин, пароль, webBasePath, subPath, UUID, REALITY SNI и ключи, клиентов и статистику**; меняет только локальные адреса веб-сервисов, сертификаты и публичные адреса подписок/хостов.
- Отключает проверку сертификата **только на TLS-соединении до `127.0.0.1`**, где работает внутренняя панель и сервер подписок (исправление прежней ошибки `502 certificate chain too long`). Внешний HTTPS остаётся с действительным сертификатом.
- Выполняет `nginx -t`, перезапускает панель и проверяет настоящие HTTP-ответы как внутреннего HTTPS, так и внешнего маршрута Nginx через TCP 443. При сбое возвращает предыдущие файлы и базу.
- Сохраняет резервную копию до изменений в `/root/3x-ui-stack-backup-*`.

**Скрипт ориентирован именно на конфигурацию 10 подключений из нашей объединённой базы.** Если в базе другое число/структура протоколов или SNI совпадают, он остановится до изменений. Успех HTTP-проверок **не равен** проверке всех VPN-клиентов из интернета.

## 6. Смена домена, возврат на SSL для IP

После успешного `after-import`:

```bash
sudo 3x-ui-change-domain
```

В меню будут варианты:

1. Добавить или изменить домен (требуется A-запись DNS на текущий публичный IPv4).
2. Удалить домен из настроек сервера и перейти на HTTPS по публичному IP, с Let's Encrypt IP-сертификатом.
3. Принудительно перевыпустить сертификат текущего адреса через `acme.sh` с резервной копией старого сертификата и проверкой панели.
4. Проверить доступность панели.
0. Выход.

При переключении между IP и доменом публичная страница на `/` остаётся без изменений. Обновляются URL подписок, связанные с управляемым адресом записи «Хосты», TLS-пути сертификатов и Nginx. Чужие или отдельные адреса пользовательских хостов, не равные **предыдущему управляемому адресу**, не переписываются. REALITY SNI `dl.google.com` и SNI других протоколов-маскировок остаются прежними. Старые SSL-сертификаты сохраняются для безопасного возврата, а DNS-запись домена автоматически не удаляется.

> Старые ссылки подписок с прежним IP/доменом не всегда перенаправятся автоматически: пользователям может потребоваться обновить URL подписки.

## 7. Диагностика и безопасность

```bash
sudo nginx -t
sudo systemctl status x-ui nginx fail2ban --no-pager
sudo ufw status numbered
sudo fail2ban-client status sshd
sudo 3x-ui-wg status
sudo /root/.acme.sh/acme.sh --list
sudo ss -lntup | grep -E ':(1335|443|13133|8444|51820|51821|51822)\b'
```

При ошибке автоматического переключения проверьте созданную резервную копию `/root/3x-ui-stack-backup-*` и системный журнал. Не запускайте повторно старую версию `3x-ui-after-import`, которая генерировала новый пароль панели и вызывала ошибку 502.

Для ручного продолжения при прерывании **только на этапе Fail2ban до установки 3x-ui** предусмотрен `resume-after-fail2ban.sh`. Нельзя использовать его, если панель уже установлена. Текущая версия установки сначала проверяет до 12 секунд готовность Fail2ban и выводит журнал при реальном сбое.

## 8. Тесты перед публикацией


Скрипты проходят локальные проверки Bash/Python, проверку наличия страницы-заглушки и страницы 404, статическую проверку WireGuard и тест копирования данных, путей, клиентов, статистики, VLESS Reality, маршрутов и перехода IP ↔ домен. **Полный end-to-end запуск на чистом VPS в этих тестах не выполняется**. ## Исправление 2.3 — проверка панели после восстановления базы

После перезапуска x-ui и вызова `acme.sh --installcert` панель может ещё запускаться.
Теперь `3x-ui-after-import` ожидает готовности внутреннего HTTPS до ~12 секунд,
проверяет внешний маршрут и статические страницы по отдельности, выводит понятный
этап сбоя и **при ошибке возвращает прежнюю конфигурацию**.
Проверка `curl` всегда выполняется без системного HTTP(S)-прокси.
При этом не изменяются логин, пароль, путь панели или UUID клиентов.

Если команда предыдущей версии завершилась с сообщением об откате, сначала
убедись, что первоначальный адрес панели снова открывается. Установщик повторно
на запускать не нужно: заменить `/usr/local/sbin/3x-ui-stack-manager` новым
`stack-manager.sh` (после резервной копии), затем повторить `sudo 3x-ui-after-import`.
Если проверка снова не пройдёт, новый журнал покажет, что именно недоступно.
